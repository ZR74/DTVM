DTVM State-Load Subphase Breakdown

This report drills into the previously identified state_load cost by separating it into state_file_read, state_json_parse, state_materialization, and state_access_warmup. The goal is to answer what part of cold-start state loading is actually dominant across the existing 200-transaction replay corpus.

Headline: for all three modes, the largest state-load component is state materialization, with file read and JSON parse following behind. Access-list warmup is negligible on this corpus.

On the full 200-transaction corpus, state materialization is the dominant state-load subphase. In current SSA Off it averages roughly 5.41 ms, compared with 2.15 ms for file read and 2.11 ms for JSON parse. SSA On is similar: about 5.64 ms materialization, 1.92 ms file read, and 1.91 ms parse. Interpreter is also dominated by materialization at about 5.57 ms.

This means the next optimization target under state loading should not be just faster file IO. The higher-return direction is reducing host/account/storage object construction and import overhead, then trimming JSON parsing, and only after that worrying about access-list warmup.
