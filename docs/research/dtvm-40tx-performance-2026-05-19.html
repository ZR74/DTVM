执行摘要

先看结论，再看细节。下面四点是当前 40 条真实交易 replay 的主结论。

重点结论

冷启动总耗时仍然由 JIT compilation 主导

当前可比 cold benchmark 中，40 条交易的整体 wall mean 为 13.07 s。 按数据集拆开看，jit_compilation_ms 与 statistics_total_ms 几乎重合，说明冷路径主要不是 host rollback，而是编译本身。

CoW mean 4.27 s ERC20 mean 16.55 s ERC-4337 mean 4.88 s UniV3 mean 26.58 s

execution-only 的最大热点是哈希，不是 EVM BB

在 40 条交易的 execution perf 中，Keccak 占 top-frame 54.98%， 远高于 EVM BB 自身的 0.32%。Uniswap V3 Swap 数据集里这个占比更高，达到 64.70%。

overall keccak 54.98% UniV3 keccak 64.70% CoW keccak 43.72%

内部调用路径确实有 host 侧浪费，而且已经修掉两块

历史 perf 里，evmHandleCallInternal 是高频 host symbol， 代表性交易还明显打在模块名重建和整表状态复制上。已经落地的两次优化分别解决了 “相同 bytecode 的重复模块装载”和“嵌套调用的全量 snapshot/restore”。

top host: CallDataLoad 1613 internal call 1340 SLoad 697

现有 perf 还存在可观测性盲区

overall unknown 28.55%，ERC-4337 Bundle 甚至达到 42.40%。这不是运行时性能本身，但它会直接降低后续热点归因的精度， 应该作为“性能分析基础设施”问题尽快补齐。

现有改动

这两项已经落地，属于当前分支上“已经完成”的优化，不是纸面建议。

Already Implemented

内部调用模块键缓存复用

现在内部调用模块按 codehash + revision + memory profile 复用， 不再为“相同 runtime bytecode，但地址不同”的调用反复做 toHex、 newSymbol 和新的模块键构造。

  • 新增 Runtime::findEVMModule(EVMSymbol) 做符号级回查。
  • 内部调用模块名从“地址导向”改为“代码身份导向”。
  • 已有回归测试覆盖“同代码跨地址复用”。
在旧的代表性交易 perf 里，ConstStringPool::newSymbol 有 360 samples，toHex 有 224 samples； 这类信号在新结果里已经不再出现在前列。

内部调用 journal rollback

嵌套 CALL 现在不再每层整份复制 accounts / logs / selfdestructs， 而是按 frame 记录增量修改，失败时只回滚当前调用真正改过的状态。

  • 覆盖 SSTORE、TSTORE、SELFDESTRUCT、余额转移、codehash lazy materialization。
  • 增加“内层 SSTORE 后 REVERT 不泄漏状态”的回归测试。
  • 对 cold total 几乎无感，但对 execution-only 的内部调用路径明显减负。
代表性 CoW 交易 0x478b92... 的同配置 execution perf： profile window 10895 ms -> 2569 ms（-76.4%）， copy-assign share 3.76% -> 1.87%。

建议的下一轮推进顺序

如果目标是“先把用户感知延迟打下来”，顺序不能反。

Recommended Order

1. 先打编译冷路径

当前 cold total 几乎就是 compile total。持久化模块缓存、tiered policy、 大字节码 compile shortcut 是最先该做的。

2. 再打 Keccak + calldata helper

execution-only 的最大块在这里。尤其 UniV3 / CoW 这类路由交易，不先碰哈希和 calldata， 只抠 EVM BB 的收益会很有限。

3. 最后继续收内部调用尾部成本

两轮内部调用优化已经把最大的伪热点拿掉了。后续继续做 O(1) warming、 no-value fast path、instance / isolation reuse，属于顺势收尾。
