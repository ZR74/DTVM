What This Means

  • 对当前 SSA Off，JIT compilation 平均只有 5.17 ms，远小于 residual wall 的 55.07 ms。
  • erc20_transfer 和 uniswap_v3_swap 的 wall 仍然最贵，但这两组的 residual wall 也都很大，说明不是单纯“编译器太慢”。
  • Interpreter 的 statistics total 几乎接近 0，进一步证明当前内部 timer 没有覆盖完整执行链路，尤其没有覆盖外层 replay/host/状态处理成本。
  • 当前 SSA On 的 wall 只比 Off 差一点，但它的 JIT 更低、P95 更好，说明编译本体有所改善，只是被冷启动外层成本淹没。

Next Profiling Directions

  • 补一层更细的阶段 timer，至少把 prepared/state 装载、JSON 解析、host call 包装、以及 VM 主执行分别计时。
  • 对最慢的 `erc20_transfer` / `uniswap_v3_swap` 单例做 `--benchmark --num-extra-executions` 与 `perf` 联合分析，把冷启动和 steady-state 分开。
  • 如果要继续优化端到端 wall，重点不应只放在 JIT 编译，而应继续追 `evmHandleCallInternal`、storage path 和外层 replay 框架。
